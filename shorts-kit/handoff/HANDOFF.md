## 1. 目的・現状・ルールと判断基準

### 目的
- 依頼主(ユーザー)は、YouTube チャンネル「ティーティーチャンネル」(@tt-channel-777、以下 tt)の切り抜き担当として契約している
- tt の長編(トレカの PSA / ARS 鑑定結果の開封動画)から、本人の声と映像だけでショートを作る
- 目標: tt の登録者 1,000 人(2026-11-09 時点 732 人)、ショート 1 本で 1 万再生
- **主な指標は「本編到達数」**(ショートの関連動画リンクから長編に来た数)。判定は投稿 7 日後。Studio の数字はユーザーから送ってもらう(こちらからは Studio に入れない)
- 補助の指標: 48 時間の再生、高評価率、登録者の増え方(公開値。`tracker.py` で毎日取る)

### 現状(2026-11-09)
- ここまでに切り抜きショートを 10 本投稿(一覧は `tt_shorts_latest.csv`)
- 最新のミュウツー(IEddhHSaoaY、11/07 投稿)が 3 日で 8,537 回。tt の切り抜きで過去最高(それまでは究極竜 5,222)
- 書き出し済み・未投稿: 「悩み別の答え」4 本(PSA48 枚の回)。`output/variant_psa48_qa{1..4}_QA.mp4`(output は git 管理外。再生成の手順は 5 章)
- 7 日判定の Studio の数字は、まだ 1 本ももらえていない

### 制作の手順(このスタジオの決まり。`CONTRACT.md` が原本)
1. ユーザーが gigafile で長編を送る → ダウンロード → 文字起こし(`transcribe.py`)
2. 切り抜きリスト(候補 5〜7 案に点数)を作り、画像でも見せる(`briefs/*_cliplist.md`)
3. 選ばれた案の**絵コンテを先に**見せる(`storyboard_variants.py plan.json src.mp4 --out-dir output`)
4. 承認後に書き出し(`--video <型>`)→ `critic.py` で検品 → 静止画を並べて目で確認 → 送る
5. 投稿文セット(2 案以上)を出す → ユーザーが選ぶ/手直しする → 確定版を `copy/` に残す
6. 投稿後は毎日の数値チェックで実験ログ(`PLAYBOOK.md` 6 章)に記入

### 判断基準(ユーザーとのやり取りで決まったこと)
- 使うのは元動画の映像・声・字幕と、承認済みの文言だけ。**金額・枚数・カード名を作らない**。足りなければ止まって聞く
- 声は**本人の声だけ**。ナレーションを作らない。AI 生成の映像は使わない(サムネで AI が別のカード文字を描いていたのを指摘し、作り直した)
- 結果を偽らない(PSA9 を PSA10 と演出しない)
- 1 回の試しで変えるのは 1 か所だけ(どれが効いたか分からなくなるため)。ミュウツーは 4 か所同時に変えたので、効いた理由は未確定
- 伸びた理由の仮説(確信度は中〜低): 小さな元手→大きな結果 / 話題中のカード(ドラゴンボール高騰・究極竜) / 結果をタイトルで伏せる / 答えを前半に出す短い尺
- 「悩み別の答え」(記事『つなぐではなく分解する』)は試し始めたところ。結果の瞬間型と 7 日で比べる

## 5. 定期作業の手順

### 毎日 20:49(日本時間)数値チェック(自動で届く)
1. `cd shorts-kit && git pull`
2. `python3 tracker.py snapshot`(YouTube が 403 なら 1 回だけ再実行)
3. `python3 tracker.py report --hours 24` と `--hours 48`
4. tt で投稿 48 時間のショートがあれば `PLAYBOOK.md` 6 章に 48h 再生・高評価率・登録者増と判定を書く
5. nori は投稿 7 日目に「7日再生÷中央値3,677・高評価率・コメント数」を `PLAYBOOK.md` 4.998 に。登録者の週の増減も
6. TikTok ポケカ沼はフォロワー・いいね計・投稿数の増減を報告
7. `data/snapshots.jsonl` と PLAYBOOK を commit・push(拒否されたら fetch+merge してから push)
8. 報告は「結論→根拠→アクション→代替案→リスク」で短く。変化がなければ 1 行「変化なし」

### 新しい長編が来たとき(ユーザーの依頼ごと)
1. gigafile: ページを開いて cookie を取り、`download.php?file=<ID>` を同じ cookie と Referer で取得
2. `ffmpeg -i src.mp4 -ac 1 -ar 16000 audio.wav` → `python3 transcribe.py audio.wav --model-dir <ReazonSpeech> --vad <silero> --out src.srt`(モデルは sherpa-onnx-zipformer-ja-reazonspeech-2024-08-01 と silero_vad.onnx。環境に無ければ再取得)
3. 静止画を一定間隔で並べて字幕(金額)を読む → 切り抜きリスト → 絵コンテ → 書き出し(1 章)
4. 書き出し後: `critic.py`、ラウドネスが外れたら loudnorm をもう一度。ユーザーが冒頭 2 秒を自作するので、**頭に 0.6 秒の無音**を足す(tpad + adelay)

### 再生成のコマンド(output は git 管理外)
- `python3 storyboard_variants.py scripts/mewtwo_psa.json <src.mp4> --out-dir output --video TL25`
- 悩み別 4 本: `scripts/psa48_qa.json` を 1 本ずつに分けて `--video QA`(この会話では scratchpad に qa1〜4.json を作って実行した)

## 7. トーン・やってはいけないこと・注意点

### 表現
- 画面の型(今の基準): 上に見出し(極太・黄/白+黒フチ)、中に元動画(**拡大しない**。横幅いっぱいまで)、下に情報(時系列の段・レシート等)
- 1 画面 1 メッセージ。上の文字は 1 行 13 字以内。同じ情報を画面の 3 か所で言わない(視線が散る。80倍の判子はこの理由で外した)
- 効果音は控えめに。ユーザーが消したもの: 冒頭のドン、ドラムロール、高い「ピョン・ピン」、大きいシュッ。残しているのは控えめなシュッ・結果のドン・レジ音(声より大きくしない)
- 回転の向き: 強調の判子は右肩上がり
- YouTube の UI(右端のボタン・下約 20%)に文字をかけない

### 投稿文の型(`copy/TEMPLATE.md`)
- 【タイトル】【説明文】【タグ】。2 案以上。結果を伏せる案を推奨
- タイトルは最初の画面・サムネと言葉を重ねない。金額はタイトルに 1 つまで。【】は必須ではない
- **サムネ=夢、タイトル=サムネに無い不安/カード名、説明文=背景の事実と誘導、タグ=表記ゆれだけ**(結果は書かない)
- URL は書かない。「全編は関連動画をチェック😎」。チャンネル紹介文の末尾は「✌🏽」
- 「本人いわく」などの言い回しは使わない
- 相場の注記を入れる(撮影時の相場であり購入額・売却額とは異なる)

### やってはいけないこと
- 数字・カード名・結果を作る、盛る、偽る
- 本人以外の声・AI の映像を使う
- ネットワーク制限の回避(YouTube・X の取得をミラーやボット偽装で取るのは過去に止められた)
- 性的な描写の話題(ブルマの回は外した)
- 実在のロゴ・報道機関の名前を使った演出

### 注意点
- 同じブランチに他のセッション(FX・タンガテーブル)も push する。push 前に fetch+merge
- 長編ファイルと文字起こしは scratchpad にあり、環境が変わると消える。gigafile のリンクも期限切れになる
- 公開の登録者数は丸めた値(誤差あり)
- ユーザーへの返答は日本語。結論を先に、確信度を付ける。完了報告には検証の証拠を付ける
