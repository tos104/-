## 7. 表現のトーン・やってはいけないこと・注意点

### トーン
- 説明は短く言い切る。専門用語は出した直後に「つまり何か」を絵や ( ) の言い換えで見せる
- 冒頭は見ている人への問いかけか、失敗の場面(「〜した瞬間に買うと…」「含み損、我慢してない？」)
- 動画の言葉は元動画の発言そのまま。言い換えた所は「補足(要承認)」と書いて分ける
- 投稿文は `shorts-kit/copy/TEMPLATE.md` の FX のルールに従う。タイトルに冒頭画面の文字を重ねない。2 行目は「誰の悩みか+答えの一言」。入り方には MAribbon の条件を必ず入れる
- ユーザーへの報告: 日本語、結論(30〜80字)→根拠→アクション→代替案→リスク。事実と推測を分け、確信度(高・中・低)を書く。浅い称賛や定型句は書かない

### やってはいけないこと
- 利益額・pips・勝率・「必ず」「勝てる」を書く/出す(金融庁は SNS から売買へ誘導する一連の行為も問題になり得るとしている)
- 相場の予想・特定の売買の推奨(免責「教育目的であり、金融・投資助言ではありません。取引判断はご自身で行ってください。」を必ず入れる)
- FX 会社の名指し
- 本人の確認が要る内容(元ディーラーの経歴の話・本人の失敗談・金額)を使う(11-07 の方針)
- 書籍『読まないFX』の文章の転載(無断転載禁止 p.2)。要点を図にするだけ
- 被害報告の出ている件・私的な話(家族・相続)・市販の曲(のりラジオの後半)を使う
- 依頼されていない変更を入れる(「ついで改善」禁止。見つけたら提案として列挙)
- 実行していない検証を「動くはず」と書く。同じエラーへの修正は 2 回まで
- 自殺・希死念慮に関する案内やメッセージを出すこと(ユーザーの明確な指示。1 文字も出さない)

### 注意点(技術)
- `output/` は git に入らない(.gitignore)。動画・素材はコンテナが消えると無くなる → このパッケージの zip で渡している
- 書き出し後は `git checkout -- shorts-kit/__pycache__/` と `rm -f shorts-kit/__pycache__/chart_short*.pyc`(追跡中の pyc が書き換わるため)
- 重い書き出しを 2 つ同時に走らせない(メモリ不足で落ちた)。バックグラウンドで走らせる時は絶対パスで
- VOICEVOX は自分で起動する: `scratchpad/vv/linux-cpu-x64/run --host 127.0.0.1 --port 50021`(エンジンは 7z から展開。新しいコンテナでは再取得が要る)
- `critic.py` の「画面変化の平均間隔」「止まって見える区間」は、画面を切り替えない作りでは必ず FAIL になる(判定と合わない)。扱いは未決定
- 文字起こしは `transcribe.py`(sherpa-onnx + ReazonSpeech)。VAD で切れて聞き取れない所は、VAD なしで 10〜16 秒ずつ区切って聞き直すと取れる(1107 の「残る」「儲かってくる」はこれで確認)
- 元動画は gigafile で受け取る。ページの cookie を付けて `download.php?file=<ID>` で取れる

## B. 動画 1 本を作る手順(毎回)
1. **素材を受け取る**: ユーザーが GigaFile の URL を渡す → `output/<案件>/` に保存。ページの cookie を付けて `download.php?file=<ID>`
2. **中身を確かめる**: `ffmpeg -i src.mp4 -ac 1 -ar 16000 audio.wav` → `python3 transcribe.py audio.wav --model-dir <ReazonSpeech> --vad <silero_vad.onnx> --out src.srt`。数秒おきのコマを並べて画面を見る。聞き取れない所は VAD なしで区切って聞き直す
3. **案を出す**: 入り口動画か信頼動画かを決める。PLAYBOOK 4.31(冒頭フック 4 分類)・4.9986(疑問の順)・4.9987(デザインの使い分け)・4.9989(型)を当てる。冒頭の型を絵コンテに書く
4. **絵コンテ**(関門 2・ユーザーの承認が要る): 各カットに秒・見ている人の疑問・元動画の時刻・効果音を書いた一覧画像を出す
   - 手法の動画: `chart_short.py --board`(1022 v15 の形)。素材は高画質のスクリーンショット(`pics`)
   - 入り口動画: `neon_short.py --frames`(図解ネオン白版・`fx_spread_learn.py` が舞台)
5. **台本**: `shorts-kit/scripts/<名前>_vN.json`。直したら版を上げる(上書きしない)。`briefs/<名前>.md` に「## vN: ユーザー指示」として変更点を追記
6. **書き出し**: `python3 chart_short.py scripts/X.json --out output/X.mp4`(または `neon_short.py`)。重い書き出しは 1 本ずつ
7. **検品**(関門 4): `python3 critic.py output/X.mp4 --sheet output/X_sheet.png` → コンタクトシートを目で見る。音量は `ffmpeg -af ebur128=peak=true` で -14 LUFS 前後か確認
8. **声**: VOICEVOX を起動 → 台本の各カットに `"say"` を入れる → 声の長さに合わせて `dur` を延ばす → `"voice"` `"say_speed": 1.2` `"loudness"` を入れて書き出す
9. **投稿文セット**: `copy/<名前>_vN.md`(タイトル 3 案・説明文 A/B・固定コメント・タグ・人が確認すること・出典)
10. **納品**: 動画・コンタクトシート・投稿文をユーザーに送る。コミットして作業ブランチに push。知見は PLAYBOOK に書いて `claude/shorts-kit` にも push
11. **投稿後**: 予約タスクの数値チェックが 7 日後の数字を PLAYBOOK に入れる → 型・仮説を更新
