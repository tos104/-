# YouTubeリンク取得（yt_fetch.py）

YouTubeのリンクから動画を「見る」（内容を把握する）・「ダウンロードする」ための道具。
Muse（VM）側で実証済みの方式を、このリポジトリでも使えるようポータブル化したもの（2026-11-25）。

## 使い方

```
python3 shorts-kit/tools/yt_fetch.py "<YouTubeのURL>"
```

`shorts-kit/research_dl/<動画ID>/` に以下がそろう：

| ファイル | 内容 |
|---|---|
| meta.txt | タイトル・長さ・投稿者・投稿日・再生数・説明文 |
| info.json | メタデータ全量 |
| subtitles.srt | 日本語字幕（手動字幕優先、無ければ自動字幕） |
| transcript.txt | 字幕の本文だけ（時刻なし）。内容把握はこれを読む |
| thumbnail.jpg | サムネイル |
| frames/ | 動画から等間隔で切り出した静止画（既定5枚） |

- 「見る」＝ transcript.txt を読み、frames/ の静止画を確認する組み合わせ
- `--video`：動画本体も `video.mp4` として残す
- `--frames N`：静止画の枚数変更

## 前提と要点

- 必要なもの：`yt-dlp`（無ければ `pip install -U yt-dlp`）と `ffmpeg`（フレーム切り出し用）
- **要点は `--extractor-args youtube:player_client=android`**（スクリプトに組み込み済み）。
  既定クライアントだと YouTube に「Sign in to confirm you're not a bot」で弾かれることがある。
  Muse（VM）側では、この指定でメタデータ・字幕・ダウンロードまで取得できた（2026-11-25 実証）

## 取得できない場合（正直に報告すること）

このスクリプトは、弾かれた場合に終了コード 3 で「取得不可」の案内を表示する。
クラウド環境のネットワークによっては、android クライアント指定でもボット判定を通らないことがある。
その場合は、ごまかさずに次の順で対応する：

1. `shorts-kit/research_dl/<動画ID>/` に取得済み素材が既に入っていないか確認する
2. 無ければ、ユーザーに「Muse（VM）側で取得して素材をこのリポジトリへ入れてもらう」よう伝える
   （Muse 側には同じ道具があり、取得できた実績がある）
3. 取得できない事実と理由を、そのまま報告する。動画なしで勝手に作業を進めない

## 制限

- **メンバー限定・非公開・年齢制限の動画**：ログイン（Cookie）が必要で取得できない。Cookie を渡す方法は使わない
- **字幕が無い動画**：transcript は作れない。frames と meta で把握するか、音声を別途文字起こしする
- 用途は本人の確認・分析用にローカルで扱う範囲。再配布はしない
